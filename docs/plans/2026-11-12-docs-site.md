## Context

Issue [#205 "needs a definitive guide and wiki"](https://github.com/smartwatermelon/mac-server-setup/issues/205): the project outgrew its docs. There are 47 tracked `.md` files (about 15k lines). They go stale, they overlap, and a new adopter has no single start-to-finish path. The README also says app setup runs automatically after reboot. That is wrong: `first-boot.sh:1442` tells you to run `run-app-setup.sh` yourself.

Outcome: a public, cross-linked, searchable docs site. Every current doc either moves into it or is listed in its "Design history" section. CI checks keep the site from drifting away from the code.

Decisions made by Andrew (2026-11-12):

1. **Platform:** GitHub Pages, built with **Zensical** from `docs/` and checked in CI on every PR. It uses the `mkdocs.yml` format, so Material for MkDocs is the fallback. The GitHub Wiki tab stays off. (Search engines do not index a wiki under 500 stars, and wiki edits skip review.)
2. **Sensitive data:** scrub and generalize. Pages use placeholders (`YOUR_SERVER`, `example.com`, `192.0.2.x`). TILSIT-specific values move to a private operator note. Git history keeps the old values; we accept that.
3. **History:** plans, archive and the old code review appear under a "Design history" section. They are scrubbed, but otherwise not edited. Navigation and search favor the current pages.
4. **PR flow:** stacked PRs. Each phase branches from the previous phase's branch, and Andrew approves the merges in batches. Goal mode stops only at a real human gate. After a lower PR merges, rebase the stack with `git rebase --onto`.

Out of scope: the referral and partnership idea in #205. It gets its own new issue at the end.

## Hard rules for this project

- **Nothing deploys to Pages until Phase 2 (scrub) has merged.** Phases 0 and 1 build in CI only.
- **No sensitive literal goes into any committed file.** That includes the sensitive-data test itself.
- Repo docs keep the repo's normal voice. STE is for chat only. Use `asd-ste100` on runbook steps only where a step reads ambiguously.
- Every move or rename updates every code, test and `CLAUDE.md` reference in the same PR. `tests/docs-references.bats` enforces this.
- Each doc path is fixed once, in Phase 3. Later phases add new pages beside it and never move it again.

## Information architecture (final paths, fixed in Phase 3)

```
docs/
  index.md                    landing: what it is, stack diagram, "start here"
  get-started/                TUTORIAL: one numbered path, prereqs → first play
    01-choose-stack.md 02-prerequisites.md 03-configure.md 04-build-package.md
    05-first-boot.md   06-operator-login.md 07-run-app-setup.md 08-verify.md
  components/<name>.md        HOW-TO hub per component; the moved app READMEs land here
    caddy cloudflare-tunnel cloudflare-ddns home-vpn monitoring pia-vpn plex
    plex-watchdog rclone stable-signing transmission-filebot tvmaze-scrobble ...
  reference/                  config-keys (generated), launchagents, logs, ports, scripts, glossary
  explanation/                architecture, tls-strategy, credential-chain, storage-virtiofs,
                              tunnel-security-layers
  troubleshooting/            symptom → cause → fix, per area
  plans/                      STAYS WHERE IT IS (planning skills and code use this path); nav: History
  archive/                    STAYS; nav: History; the old code review moves here
```

Code and alert text point at `components/<name>.md` (repo path in comments, site URL in alert text). A component page may later link out to new explanation and reference pages, but its own path never changes again.

**Phase 2 outcome (2026-11-12):**

The scan failed on the unscrubbed tree before any fix. The PR lands in two commits, because `README*` files need copy approval: the first scans every page except README-named ones, and the second scrubs those and widens the scan to all pages.
